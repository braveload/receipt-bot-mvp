# 영수증봇 프로젝트 진행 상황 정리

> 최종 업데이트: 2026-07-24

## 1. 프로젝트 개요

**영수증봇**: 프리랜서/1인 사업자를 위한 카카오톡 기반 영수증 자동 정리 챗봇 SaaS.
카카오톡으로 영수증 사진을 보내면 상호명·금액·날짜·카테고리·사업/개인 구분을 자동 추출해
저장하고, "이번달"이라고 물으면 요약을, 신고철 요청 시 세무사 전달용 엑셀을 제공한다.

### 2.4 OCR/추출기 — Claude Vision → Google Vision 전환
- 최초 설계는 Claude Vision 단일 호출로 OCR + 분류를 한 번에 처리하는 방식
- **문제 발생**: Anthropic API 크레딧 미결제로 "credit balance too low" 오류
  - Stripe Link 전화번호 인증 등으로 실제 결제가 막힘
- **사용자 결정**: 우선 `EXTRACTOR=mock`으로 테스트 지속 → 이후 무료 대안인
  **Google Cloud Vision API**(월 1,000건 무료)로 교체하기로 결정
- Google Cloud 프로젝트 생성(`receipt-bot-ocr`, ID: `receipt-bot-ocr-502922`) →
  Cloud Vision API 활성화 → API 키 발급(Cloud Vision API로 사용 제한) → Render에
  `GOOGLE_VISION_API_KEY` 환경변수 등록 및 `EXTRACTOR=google` 전환

#### 아키텍처 차이 (Claude Vision vs Google Vision)
Google Vision은 텍스트 추출(OCR)만 하고 "이게 상호명/금액/카테고리다"라는 판단은
해주지 않는다. 그래서 `extractor.py`에 규칙 기반 파싱 함수 `parse_receipt_text()`를
새로 구현해서 정규식/키워드로 상호명·금액·날짜·카테고리를 뽑아내도록 했다. 이 경로로
추출한 결과는 정확도가 낮을 수 있어 confidence를 0.5로 고정해두고, 카카오톡 응답에
항상 "확인 필요" 안내가 붙게 했다.

### 2.5 버그 수정 (실제 이미지로 검증하며 발견)
1. **`main.py` — 설정 오류 시 500 에러**: `get_extractor()`가 try/except 밖에 있어서
   `GOOGLE_VISION_API_KEY` 미설정 시 처리되지 않은 500 에러가 났음. try 블록 안으로
   이동시켜 친절한 안내 메시지로 대체.
2. **금액 추출 버그 #1 — 전화번호를 금액으로 오인식**: 영어 영수증 샘플 테스트에서
   `9,880,123,123원`처럼 전화번호가 금액으로 잡힘. 콤마 없는 8자리 이상 숫자는
   후보에서 제외하도록 수정.
3. **카테고리 오분류 버그 — "kt" 오탐**: 청구서 번호 `SI37482-MKT-90/81`의 "MKT" 부분이
   통신사 키워드 "kt"와 부분 문자열 매치되어 "통신비"로 잘못 분류됨. 2글자 이하 키워드는
   단어 경계(`\b`) 매칭만 허용하도록 수정.
4. **금액 추출 버그 #2 — 여전히 오답**: 디버그 로그로 실제 OCR 결과를 확인해보니
   "Net Amount"라는 라벨과 실제 금액 "185.00"이 서로 다른 줄로 인식되고 있었음
   (열 레이아웃 영수증의 흔한 OCR 특성). 라벨이 있는 줄에 숫자가 없으면 다음 줄도
   확인하도록 `_guess_amount` 로직 확장. 최종적으로 실제 영수증 사진 기준
   `Saathimart.com · 185원 · 개인 지출로 분류 (기타)`로 정확히 추출 성공 확인.

이 버그 수정들은 모두 GitHub에 반영 후 Render 재배포하여 실제 배포 환경에서 재검증했다.

### 2.8 확인·수정·저장 및 신고파일 보안
- OCR 직후 레코드를 `draft` 상태로 저장하고 카카오 빠른 답장 `저장`·`수정`·`확인` 제공
- `수정 항목=값; 항목=값` 명령으로 상호명, 금액, 날짜, 증빙유형, 카테고리,
  사업/개인 구분, 사업자번호를 검증 후 수정
- `저장` 명령을 받은 레코드만 월간 요약과 엑셀에 포함
- 엑셀 다운로드를 HMAC SHA-256 서명 링크로 변경하고 기본 10분 만료 적용
- 만료 링크는 410, 위조 링크는 403으로 차단하며 사용자 ID 대신 해시 파일명 사용
- pytest 자동 테스트 12개와 기존 데모 2종 통과

## 4. 알려진 제약/리스크

- Google Vision 경로는 규칙 기반 파싱이라 특이한 레이아웃/키워드 사전에 없는 업종에서
  오분류 가능성 있음 (`extractor.py`의 `_CATEGORY_KEYWORDS`에 키워드 추가로 개선 가능)
- Render Free 티어 콜드스타트로 인해 첫 요청 응답이 느릴 수 있음
- 원본 영수증에는 카드번호 등 민감정보가 있을 수 있어 접근 권한과 보존기간 관리가 필요
- 운영 저장소는 Neon PostgreSQL이며 로컬·테스트만 SQLite를 사용
- 월간 요약은 현재 사용자가 먼저 물어야 응답하는 수동 방식 (선제적 발송은 카카오톡
  친구톡/알림톡 API 별도 연동 필요)

## 5. 주요 기술 스택/구조

```
receipt-bot-mvp/
  app/
    main.py            FastAPI 웹훅 서버 (카카오 스킬서버 엔드포인트)
    kakao_adapter.py   카카오 payload 파싱 + 응답 포맷
    extractor.py       영수증 이미지 → 정형 데이터 (Mock / Claude Vision / Google Vision)
    storage.py         SQLite 저장
    report.py          월간 요약 텍스트 + 엑셀 내보내기
  demo/
    run_demo.py        전체 흐름 검증용 데모 스크립트
  tests/               pytest 자동 회귀 테스트
  docs/                사업모델 설계서와 진행 문서
  marketing/           홍보 문구와 이미지 자산
  site/                랜딩페이지와 신청 완료 페이지
```

- 배포: Render.com (Free 티어)
- OCR: Google Cloud Vision API (`TEXT_DETECTION`, 한국어 힌트)
- 저장소: GitHub `braveload/receipt-bot-mvp` (공개 레포)
- 챗봇 플랫폼: 카카오 i 오픈빌더
